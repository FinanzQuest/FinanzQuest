# =============================================================================
# FinanzQuest DB init manifest — SINGLE SOURCE OF TRUTH for any runner script.
# One relative path per line; execute strictly in listed order. Lines starting
# with '#' are comments (runner must skip them). Do NOT rely on find | sort or
# alphabetical traversal anywhere.
#
# Execution is TWO phases:
#   Phase 1 (PRE-GoTrue):  00-preauth/01_auth_admin.sql
#     The only block GoTrue needs before it starts.
#   Phase 2 (POST-GoTrue): everything from 01-schema onward, then seed/.
#     Run after the auth service is healthy (it creates auth.users etc.).
#
# Ordering inside each phase is dependency-ordered, NOT alphabetical.
# Key within-folder orderings that differ from plain sort:
#   - 03-tables/api/: assets.sql BEFORE asset_prices.sql (asset_prices FK -> assets)
#   - 06-views/depots/: values.sql BEFORE aggregated_values.sql, and
#     leaderboard.sql AFTER values.sql + users/profile.sql
#   - 04-functions/: leaf helpers before their callers; users/ before depots/
#     so depots functions that call users.has_any_role come after it
#   - 08-roles/: every CREATE ROLE before any GRANT <role> TO <role> that
#     references it (authenticator -> anon -> authenticated -> service_worker
#     -> view_refresher)
# Cross-phase (documented): depots.get_depot_overview reads users.profile (a
# 06-view) and users.has_any_role; both are resolved at CALL time (plpgsql
# bodies are not validated at CREATE), so it is safe to create the function in
# phase 2 before the view exists.
# =============================================================================
